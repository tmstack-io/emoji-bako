# 使用回数の同期は、Macごとの欄とリセットの世代番号でiCloud KVSに持つ

同じAppleアカウントのMac同士で使用回数を同期するために、iCloudのキーと値の保存（`NSUbiquitousKeyValueStore`、以下KVS）を使う。KVSは、同じキーに複数のMacが書き込むと最後に書いた値だけを残す。そのため、使用回数の辞書を1つのキーに入れて全Macで書き換えると、オフラインのあいだに別のMacで数えた回数が失われる。

そこで、各Macは自分専用の欄（`mac.<ランダムなID>`）にだけ書き込み、表示には全Macの欄の合計を使う。リセットに対応するため、全Macで共通のリセットの世代（`generation`。世代番号とリセットした日時）を置き、各欄には「どの世代で数えたか」を記録する。合計に入れるのは現在の世代の欄だけとする。世代が進んでいたときに使用回数を消すのは、そのリセットが、このMacが同期に加わったあとに行われた場合だけとする。iCloudのデータが届く前に同期をオンにしたMacが、加わる前のリセットで使用回数を失わないようにするため。複数のMacが書くキーは、後勝ちで上書きされても困らない形に限る。`generation`は手元の値と比べて大きい方を採り、同期から外したMacの記録は1台ごとに別のキー（`removed.<ID>`）に置いて消さない。

KVSを使うと、配布するアプリにiCloudを許可するプロビジョニングプロファイル（Developer ID用）を埋め込む必要がある。プロファイルはDeveloper ID証明書と結び付くため、証明書を作り直したらプロファイルも作り直す。

## Considered Options

- **辞書1つを全Macで上書きする**: 実装は最も単純だが、2台で同時に使うと片方の回数が失われるため採らない。
- **CloudKit**: データの型の定義や本番環境への反映が必要で、小さな辞書を1つ同期する用途には大きすぎる。
- **iCloud Driveのファイル**: ファイルの競合を自前で解決する必要があり、KVSより手間が増える。
- **使用回数ごとに時刻を記録してリセット後の分を残す**: リセットを知る前にオフラインのMacで数えた回数を残せるが、1回ごとに時刻を保存する必要があり、Macの時計のずれで判定を誤る。リセットは頻繁に使う操作ではないため、世代番号で一括して捨てる方を選んだ。一方、リセットした日時と同期に加わった日時の比較には時計を使う。比べるのはリセット1回につき1つの日時なので、時計が数分ずれても、リセットと同期をオンにする操作がその数分以内に重なったときにしか影響しない。

## Consequences

- Macごとの欄は、そのMacを「同期から外す」か、すべてのMacのリセットをするまで残る。使わなくなったMacの使用回数も合計に入り続ける。
- KVSの上限（1MB、1,024キー）に対して、欄は1台あたり数KB程度で、Macが数十台あっても収まる。
- iCloud上のデータ形式（キー名と欄の中身）を変えると、古い版のEmojiBakoと同期できなくなる。変えるときは、キー名を変えて別の保存先として扱う。
